The Windows validation workflow prepares a build and native install-policy evidence without publishing a Release. It runs on pushes to `codex/offline-review-updates` or manual dispatch, using a fresh `windows-2025` GitHub-hosted x64 runner. The workflow has `contents: read`, checks out the current wrapper branch, reads the exact game, assets, locales, and pnpm pins from `build/local-macos-build.json`, installs locked dependencies, runs `npm test`, builds the Windows x64 NSIS installer, and generates and verifies the actual release manifest against the staged revisions and installer bytes.

The install script refuses to run unless `GITHUB_ACTIONS=true`, `RUNNER_ENVIRONMENT=github-hosted`, and the host is Windows x64. Before downloading or installing anything, it requires that no PokeRogue Electron uninstall registration, app-data directory, or default install directory exists. It then verifies the downloaded v0.1.3 manifest against SHA-256 `3aae963d64b62837bc64996b8d78696c7dfc1e873200e4104bf4d8a490247599`, checks the published Windows x64 entry, downloads the v0.1.3 installer, and verifies its size (`617955235` bytes) and SHA-256 (`a6bc3428b5903962fa1c8dda81291d6b0aaf84886f7856a01acb2d34612176b7`) before execution. These values were checked against the public v0.1.3 release manifest and GitHub release asset metadata on 2026-10-04.

On the fresh profile, the script silently installs v0.1.3, writes an inert sentinel, a valid keymap, and a neutral cheat document, then silently upgrades to the current installer. It records and compares the per-user uninstall registry identity and install location, verifies the new display version, and hashes the files before and after upgrade. It then uninstalls silently and checks that the registration and installed uninstaller are gone while the files remain, as configured by `deleteAppDataOnUninstall: false`. NSIS normally forks its uninstaller; the validator runs an owned copy with `/S _?=<recorded installation>` to observe the actual exit code and completion. The script never removes app data. If a check fails after installation, it attempts cleanup with that installation's own per-user uninstaller and records the outcome.

These files establish preservation policy for the sentinel files and neutral configuration. The separate opt-in [packaged Backup matrix](../backup-consistency.md#r20-unchanged-packaged-windows-proof) exercises the unchanged executable with disposable Local Storage and synthetic IndexedDB, all four cold continuations, and failure recovery. Windows CI runs that matrix against its freshly built package, then runs install/upgrade/uninstall on the hosted machine. Compact JSON/event evidence is retained separately from the installer for seven days. Offline gameplay, native remapping within the upstream game, and opening the actual verified installer still require hands-on validation. No installer was executed on the maintainer machine, and #19 remains open until its remaining criteria pass.
